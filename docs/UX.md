# UX.md — Ratatoskr 操作仕様

このドキュメントは実装の自由度が最も低い。**ここに書かれた挙動を「改善」しないこと。** 一見冗長・不自然に見える仕様には理由があり、その多くは livedoor Reader / LDRoid で実証済みのものである。

## 貫かれている原則

1. **判断させない。** 「この記事を読んだか」「次に何を押すか」をユーザに考えさせない
2. **待たせない。** キー入力に対する応答でネットワークを待つ箇所を作らない
3. **押すキーを減らさない。同じキーで済ませる。** モード切替やメニュー階層を作らず、同じキーが文脈に応じて連続的に振る舞う

## 画面構成（PC）

```
┌────────────────────┬────────────────────────────────────┐
│ ▾ (12) Foo         │  (3/12) Foo          ← ヘッダ      │
│                    ├────────────────────────────────────┤
│   1 読んだ記事     │  記事タイトル                      │
│   2 読んだ記事     │  by author / 2026-08-15            │
│ ▸ 3 いま読んでる   │  ──────────────                    │
│   4 未読の記事     │  本文                              │
│   5 未読の記事     │                                    │
│ ▸  (3) Bar         │                                    │
│ ▸ (28) Baz         │                                    │
└────────────────────┴────────────────────────────────────┘
```

- 左ペインはレート降順、同率は未読数降順。**この順序が読む順序であり、先読み順序でもある**。レートの値そのものは表示しない（並び順としてだけ効く）
- 未読 0 のフィードは未読数を表示しない（`(0)` を出さない。LDRoid のコミット 9635ba4 と同じ判断）
- 未読数は読み進めるそばから減る（既読化のタイミングは後述）
- 記事一覧は**フィード名を押して開閉する**。カーソルは動かさない（開閉と移動は別の操作）
- **読んでいる最中のフィードは自動で開き、離れれば閉じる。** 手で開いたものは閉じるまで開いたまま（読んでいる場所を見失わずに他のフィードを覗けるように）。既定で全フィードを展開はしない
- 読んでいるフィードを手で畳んでも、**カーソルが動いたら開き直す**。記事を送っている最中に一覧が出てこないと現在地が分からなくなる
- 開いた一覧の記事を押すと、そのフィードに移ってその記事を表示する
- 記事一覧では**既読の記事を暗く**する。どこまで読んだかが一目で分かる
- フィード名は一覧の上端に貼り付ける（記事が多いと現在地を見失うため）
- 右ペインは**常に 1 記事のみ**を表示する。記事リストは作らない
- ヘッダに `(現在位置/総数) フィード名` を出す。本文と一緒にスクロールさせない

## キーバインド

定義は `web/src/lib/keymap.ts` に一元化する。ヘルプ画面（`?`）はこの定義から自動生成すること。

| キー | 動作 |
| --- | --- |
| `j` | 次の記事 |
| `k` | 前の記事 |
| `s` | 次のフィード |
| `a` | 前のフィード |
| `Shift+S` | このフィードを全て既読にして次へ |
| `Space` | スクロール、下端で次の記事、最終記事で次のフィード |
| `Shift+Space` | 逆方向に同じ |
| `v` | 元記事を新しいタブで開く |
| `p` | ピン |
| `z` | ピン一覧の表示／非表示 |
| `o` | ピンを全てタブで開く（ピン一覧表示中） |
| `r` | 手動更新 |
| `1`–`5` | 現在のフィードのレートを変更 |
| `u` | 現在の記事を未読に戻す |
| `?` | ヘルプ |
| `Esc` | オーバーレイを閉じる |

入力欄にフォーカスがある間は全て無効化する。

## Space の挙動 — 最重要仕様

LDR の「Space だけ押していれば読める」の実装。LDRoid の `FeedView.processKey()` を Web に移植したもの。

```
Space 押下
  └─ 記事ビューが下端に達していない？
       Yes → 1 画面分スクロール
       No  → 次の記事へ
              └─ それが最終記事だった？
                   Yes → 次のフィードへ（既読化が走る）
```

判定は次の式で行う。

```ts
const atBottom = el.scrollTop + el.clientHeight >= el.scrollHeight - 1;
```

LDRoid の原型は `webView.pageDown(false)` が `false`（もう下端）を返したら次の記事へ進む、というもの。**スクロールと記事送りが同じキーで、境界で自動的に切り替わる**点が本質。

`Shift+Space` は上方向に同じ挙動。先頭記事の先頭でさらに押した場合は前のフィードへ。

## 既読化のタイミング

**記事を表示した時点**で、その記事までウォーターマークを進める。フィードを離れる時ではない。

理由: 離脱を待つと、リンクを開いて戻ってこなかった場合や通信断で取りこぼす。

読んだところまでが残るので、途中でフィードを離れても、戻れば続きから出る。左ペインの未読数も 1 件ずつ減る。

記事を飛ばして先に進んだ場合（一覧から直接選ぶ等）、間の記事も既読になる。順に読む前提の設計であり、意図的に読み飛ばした記事を未読で残す手段は `u`（M4）を使う。

未読が溜まったフィードは `Shift+S` で一括既読にして次へ進める（LDR の `touch_all` にあたる操作）。

実装上の注意（LDRoid が実際に踏んだバグ、コミット 511b224）:

- 送信済みフラグは**リクエスト発行前**に立てる
- そうしないと、外部リンクを開いて戻ってきたときに再度既読化が走る

送るウォーターマークは「**実際に画面に出した記事の最大 entry id**」。手元に持っているだけで表示していない記事（背景取得で届いた分）を巻き込まないため。

## 境界でのボタン変化（スマホの中核）

LDRoid の `updateButtons()` の再現。

```
現在位置が最終記事でない → 「次の記事」
現在位置が最終記事       → 「次のフィード」
現在位置が先頭記事でない → 「前の記事」
現在位置が先頭記事       → 「前のフィード」
```

**ボタンは画面の同じ位置に留まり、ラベルだけが変わる。** 押し続けるだけで記事 → 記事 → フィード → 記事…と全購読を消化できる。モードもメニューもなく、親指の位置を変える必要がない。

これがスマホ UI の設計の軸。ここを崩すと LDR 体験ではなくなる。

## 画面構成（スマホ）

```
┌──────────────────────────┐
│ ← フィード名    (3/12)    │  ヘッダ（タップでフィード一覧へ）
├──────────────────────────┤
│                          │
│  記事タイトル             │
│  本文                    │
│                          │  ← 縦スクロール
│                          │
│                          │
├──────────────────────────┤
│  ◀前へ  開く  ピン  次へ▶ │  ボトムバー（固定・safe-area 対応）
└──────────────────────────┘
```

- ボトムバーは `env(safe-area-inset-bottom)` を考慮して固定
- 「次へ」は右端、最も親指が届く位置に最大サイズで配置する
- 左右スワイプで記事送り（`j` / `k` 相当）。境界を越えるとフィード移動
- フィード一覧はヘッダから開く。デフォルトの表示は記事ビュー

### スマホで実装しないもの

- プルダウン更新（スクロール操作と競合し、記事送りの妨げになる）
- 記事一覧からのタップ選択を主導線にすること（LDR の思想に反する。一覧は移動手段であって選択画面ではない）
- スワイプでの既読操作（既読は「どこまで読んだか」で表すので、個別記事を既読にする操作は概念的に存在しない）

## 記事本文のレンダリング

- 画像は `max-width: 100%; height: auto`。フィード側の `width` 属性は取り込み時に除去済み
- 本文中のリンクは `target="_blank" rel="noopener noreferrer"`
- 等幅ブロック（`<pre>`）は横スクロール可能にする。本文全体を横スクロールさせない
- **記事の切り替えにトランジションを付けない。** アニメーション時間はそのまま体感遅延になる

## ピン

- `p` でピン。トーストで短く通知する（記事は切り替えない）
- `z` でピン一覧をオーバーレイ表示
- 一覧から個別に開く、または `o` で全てを新しいタブに開く
- 「読む」と「後で処理する」を分離するための機能。ピンした記事は既読化の対象から外れない

## レート

- 1〜5。既定は 3
- **フォルダ分類ではなく「読む順」を管理するための機能**。左ペインのソート順を直接決める
- 数字キーで即座に変更できること（設定画面に潜らせない）
- レート変更後は左ペインの並びが即座に更新され、先読みウィンドウも再計算される
- **左ペインに値は表示しない。** 並び順に現れていれば用は足りる。値そのものを見たい・直したいときは購読管理画面で足りる

## ヘルプ

`?` でキーバインド一覧をオーバーレイ表示。`keymap.ts` から自動生成する。

初回起動時は自動で表示する（キーボード操作前提の UI なので、知らないと何もできない）。
