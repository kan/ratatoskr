# UX.md — Ratatoskr 操作仕様

このドキュメントは実装の自由度が最も低い。**ここに書かれた挙動を「改善」しないこと。** 一見冗長・不自然に見える仕様には理由があり、その多くは livedoor Reader / LDRoid で実証済みのものである。

## 貫かれている原則

1. **判断させない。** 「この記事を読んだか」「次に何を押すか」をユーザに考えさせない
2. **待たせない。** キー入力に対する応答でネットワークを待つ箇所を作らない
3. **押すキーを減らさない。同じキーで済ませる。** モード切替やメニュー階層を作らず、同じキーが文脈に応じて連続的に振る舞う

## 画面構成（PC）

```
┌────────────────────┬────────────────────────────────────┐
│ ▾ (12) Foo         │  (3/12) Foo          ← ヘッダ      │
│                    ├────────────────────────────────────┤
│   1 読んだ記事     │  記事タイトル                      │
│   2 読んだ記事     │  by author / 2026-08-15            │
│ ▸ 3 いま読んでる   │  ──────────────                    │
│   4 未読の記事     │  本文                              │
│   5 未読の記事     │                                    │
│ ▸  (3) Bar         │                                    │
│ ▸ (28) Baz         │                                    │
└────────────────────┴────────────────────────────────────┘
```

- 左ペインはレート降順、同率は未読数降順。**この順序が読む順序であり、先読み順序でもある**。レートの値そのものは表示しない（並び順としてだけ効く）
- 未読 0 のフィードは未読数を表示しない（`(0)` を出さない。LDRoid のコミット 9635ba4 と同じ判断）
- 未読数は読み進めるそばから減る（既読化のタイミングは後述）
- 記事一覧は**フィード名を押して開閉する**。カーソルは動かさない（開閉と移動は別の操作）
- **読んでいる最中のフィードは自動で開き、離れれば閉じる。** 手で開いたものは閉じるまで開いたまま（読んでいる場所を見失わずに他のフィードを覗けるように）。既定で全フィードを展開はしない
- 読んでいるフィードを手で畳んでも、**カーソルが動いたら開き直す**。記事を送っている最中に一覧が出てこないと現在地が分からなくなる
- 開いた一覧の記事を押すと、そのフィードに移ってその記事を表示する
- 記事一覧では**既読の記事を暗く**する。どこまで読んだかが一目で分かる
- フィード名は一覧の上端に貼り付ける（記事が多いと現在地を見失うため）
- 右ペインは**常に 1 記事のみ**を表示する。記事リストは作らない
- ヘッダに `(現在位置/総数) フィード名` を出す。本文と一緒にスクロールさせない
- **カーソルの行は、前後に 3 行ぶんの余白を残した位置に置く**（issue #5）。最小限の
  スクロールにすると読み進めるたびに現在地が下端に貼り付き、次に何が来るかも、
  フィードの終わりが近いことも見えない

## キーバインド

定義は `web/src/lib/keymap.ts` に一元化する。ヘルプ画面（`?`）はこの定義から自動生成すること。

| キー | 動作 |
| --- | --- |
| `j` | 次の記事 |
| `k` | 前の記事 |
| `s` | 次のフィード |
| `a` | 前のフィード |
| `Shift+S` | このフィードを全て既読にして次へ |
| `Space` | スクロール、下端で次の記事、最終記事で次のフィード |
| `Shift+Space` | 逆方向に同じ |
| `v` | 元記事を新しいタブで開く |
| `p` | ピンする / 外す |
| `z` | ピン一覧の表示／非表示 |
| `o` | ピンを全てタブで開く（ピン一覧表示中） |
| `r` | 手動更新 |
| `1`–`5` | 現在のフィードのレートを変更 |
| `u` | 現在の記事を未読に戻す |
| `?` | ヘルプ |
| `Esc` | オーバーレイを閉じる |

入力欄にフォーカスがある間は全て無効化する。

## Space の挙動 — 最重要仕様

LDR の「Space だけ押していれば読める」の実装。LDRoid の `FeedView.processKey()` を Web に移植したもの。

```
Space 押下
  └─ 記事ビューが下端に達していない？
       Yes → 1 画面分スクロール
       No  → 次の記事へ
              └─ それが最終記事だった？
                   Yes → 次のフィードへ（既読化が走る）
```

判定は次の式で行う。

```ts
const atBottom = el.scrollTop + el.clientHeight >= el.scrollHeight - 1;
```

LDRoid の原型は `webView.pageDown(false)` が `false`（もう下端）を返したら次の記事へ進む、というもの。**スクロールと記事送りが同じキーで、境界で自動的に切り替わる**点が本質。

`Shift+Space` は上方向に同じ挙動。先頭記事の先頭でさらに押した場合は前のフィードへ。

## 既読化のタイミング

**記事を表示した時点**で、その記事までウォーターマークを進める。フィードを離れる時ではない。

理由: 離脱を待つと、リンクを開いて戻ってこなかった場合や通信断で取りこぼす。

読んだところまでが残るので、途中でフィードを離れても、戻れば続きから出る。左ペインの未読数も 1 件ずつ減る。

記事を飛ばして先に進んだ場合（一覧から直接選ぶ等）、間の記事も既読になる。順に読む前提の設計であり、意図的に読み飛ばした記事を未読で残す手段は `u`（M4）を使う。

未読が溜まったフィードは `Shift+S` で一括既読にして次へ進める（LDR の `touch_all` にあたる操作）。

実装上の注意（LDRoid が実際に踏んだバグ、コミット 511b224）:

- 送信済みフラグは**リクエスト発行前**に立てる
- そうしないと、外部リンクを開いて戻ってきたときに再度既読化が走る

送るウォーターマークは「**実際に画面に出した記事の最大 entry id**」。手元に持っているだけで表示していない記事（背景取得で届いた分）を巻き込まないため。

## 境界でのボタン変化

LDRoid の `updateButtons()` の再現。

**このバーは PC にも出す**（issue #6）。寸法だけ変え、文言も振る舞いも同じにする。
マウスだけで読み進める道が無かったため。サイドバーの記事を選ぶ形にはしない
（一覧は移動手段であって選択画面ではない、という下記の方針に反する）。

```
現在位置が最終記事でない → 「次の記事」
現在位置が最終記事       → 「次のフィード」
現在位置が先頭記事でない → 「前の記事」
現在位置が先頭記事       → 「前のフィード」
```

**ボタンは画面の同じ位置に留まり、ラベルだけが変わる。** 押し続けるだけで記事 → 記事 → フィード → 記事…と全購読を消化できる。モードもメニューもなく、親指の位置を変える必要がない。

これがスマホ UI の設計の軸。ここを崩すと LDR 体験ではなくなる。

## 画面構成（スマホ）

```
┌──────────────────────────┐
│ ← フィード名    (3/12)    │  ヘッダ（タップでフィード一覧へ）
├──────────────────────────┤
│                          │
│  記事タイトル             │
│  本文                    │
│                          │  ← 縦スクロール
│                          │
│                          │
├──────────────────────────┤
│  ◀前へ  開く  ピン  次へ▶ │  ボトムバー（固定・safe-area 対応）
└──────────────────────────┘
```

- ボトムバーは `env(safe-area-inset-bottom)` を考慮して固定
- 「次へ」は右端、最も親指が届く位置に最大サイズで配置する
- 左右スワイプで記事送り（`j` / `k` 相当）。境界を越えるとフィード移動
- **下端でさらに上へ引くと次の記事へ進む。** `Space` が下端で記事送りに変わるのと同じ考え方で、
  読み進める向きの動きをそのまま続けると次に進む。引いている最中は「離すと次の記事へ」と出し、
  離した時点で切り替える（本文を指に追従させたり、切り替えにアニメーションを付けたりはしない）
- 逆向き（先頭でさらに下へ引く）は**割り当てない。** プルダウン更新と同じ動きになり、
  下に挙げた理由でそちらを外している以上、別の動作を割り当てても混乱するだけ
- フィード一覧はヘッダから開く。デフォルトの表示は記事ビュー

### スマホで実装しないもの

- プルダウン更新（スクロール操作と競合し、記事送りの妨げになる）
- 記事一覧からのタップ選択を主導線にすること（LDR の思想に反する。一覧は移動手段であって選択画面ではない）
- スワイプでの既読操作（既読は「どこまで読んだか」で表すので、個別記事を既読にする操作は概念的に存在しない）

## 記事本文のレンダリング

- 画像は `max-width: 100%; height: auto`。フィード側の `width` 属性は取り込み時に除去済み
- 本文中のリンクは `target="_blank" rel="noopener noreferrer"`
- 等幅ブロック（`<pre>`）と表（`<table>`）は、**そのブロックだけ**横スクロール可能にする。本文全体を横スクロールさせない
- **記事の切り替えにトランジションを付けない。** アニメーション時間はそのまま体感遅延になる
- **本文の行長は 44rem（およそ全角 44 字）で止め、余った幅は左右の余白にする。** 広い画面で端から端まで文字が並ぶと、行を折り返すたびに目が横へ大きく振られて読み進めづらい
- **見出しは大きさで本文と区別する。** 太字だけでは、強調に `<b>` を多用する記事で本文に埋もれて節が見えない。ただし本文の見出しが記事タイトルを追い越さない大きさに留める。`h1` / `h2` には節の切れ目が分かるよう罫線を敷く
- **表には罫線を引く。** 見出しセル（`<th>`）はうっすら地を敷いて区別する
- **埋め込みは消さずに読める形にする。** X のポストは本文・投稿者・日時を引用として出し（取り込み時に解決済み）、引けなかったものと動画などの iframe は「開く」リンクにする。スクリプトと iframe は通さないので、そのままでは跡形もなく消えて記事の意味が通らなくなる
- **本文に挟まる埋め込みの見分けは 4 条件で絞る。** 本文直下・単独の子でない・段落を含まない・画像と入れ子の div を持つ。前 2 つだけだと、段落を `div` と `br` で作るフィードの本文が丸ごと枠で囲まれる（手元の購読で 370 箇所の誤爆を 3 箇所まで落とした）
- 装飾の色は全て `currentColor` から混ぜて作る。明暗どちらのテーマでも文字色に対する濃さが保たれ、テーマごとの指定を二重に持たずに済む

## ピン

- `p` でピンする / 外す（同じキーで両方。押し間違いをその場で戻せる）。トーストで短く通知し、**記事は切り替えない**。通知は次の記事に移ったら消す
- ピンが立っている記事は、左ペインの一覧と記事の見出しに目印を出す。読む邪魔をしない程度に留める
- `z` でピン一覧をオーバーレイ表示。`z` か `Esc` で閉じる
- 一覧から個別に開く、または `o` で全てを新しいタブに開く
- `o` で**開けた分だけ**ピンから外す（「後で処理する」を消化したということ）。ブラウザは 1 回の操作で開けるタブ数を絞ることがあるので、**ブロックされた分はピンに残し**、その旨を知らせて一覧も閉じない
- 「読む」と「後で処理する」を分離するための機能。ピンした記事は既読化の対象から外れない

## レート

- 1〜5。既定は 3
- **フォルダ分類ではなく「読む順」を管理するための機能**。左ペインのソート順を直接決める
- 数字キーで即座に変更できること（設定画面に潜らせない）
- レート変更後は左ペインの並びが即座に更新され、先読みウィンドウも再計算される
- **左ペインに値は表示しない。** 並び順に現れていれば用は足りる。値そのものを見たい・直したいときは購読管理画面で足りる

## テーマ

- **明暗の 2 値だけ。** 「システムに従う」という選択肢は持たない。システム設定を見るのは
  **まだ一度も切り替えていない間だけ**で、初期値を決めるためだけに使う。一度でも
  切り替えたらその選択が残り、以降 OS 側の切り替えには追随しない
- **アイコン 1 つのトグル。** 出すのは**切り替えた先**の印（ライト表示なら ☾）で、
  いまの状態ではない。押して何が起きるかが分かる必要があるため。向きはアイコンだけでは
  伝わらないので、`title` と `aria-label` に文言でも持つ
- **画面の右上に置く。** 読む操作ではないので目立たせないが、探すときに迷わない場所に
  固定する（購読管理の入口と同じ考え方）
- **キーは割り当てない。** キー表に無いものを増やさない

## タブのアイコン

未読があるかどうかをタブのアイコンで示す（issue #7）。バッジは重ねない。32px に点や数字を載せても読めないので、**アイコンそのものを差し替える**。

- 未読があるとき … 通常のアイコン
- 未読が無いとき … RSS マークだけを薄いグレーに落とした版

**フォルダで絞っていても全体の未読を見る。** 絞り込みは「いま何を読むか」の選択で、「読むものが残っているか」とは別。絞った途端にアイコンが変わると、他のフォルダの未読を見落とす。

ホーム画面に追加した場合はアプリのアイコンにも点が付く（対応するブラウザのみ）。件数は出さない。出す情報はタブのアイコンと同じ「残っているか」だけにする。

## フォルダ

- **分類のためのもので、読む順は決めない。** 読む順を決めるのはレートで、左ペインの並びは
  絞り込んでもレート順のまま（`docs/ROADMAP.md` M5「フォルダは左ペインのグループ化には
  使わない」）
- **左ペインの頭でフォルダを選ぶと、読む対象がそのフォルダだけになる**（issue #3）。
  一覧に出るフィードも、`s` / `a` で辿る先も、画像を先読みする範囲も同じように狭まる。
  「今日は開発系だけ読む」ための機能
- **キーは割り当てない。** キー表に無いものを増やさない（購読管理の入口と同じ考え方）
- **覚えておかない。** 再読み込みで解除する。絞ったまま忘れると、未読があるのに
  「もう読むものが無い」ように見える
- **読み終えた画面は範囲を明かす。** 絞っているときは「『開発』は全て読み終えた」と
  フォルダ名を出し、範囲の外に未読があればその数も出す。狭い画面では絞り込みの表示
  そのものが引き出しの中なので、これが無いと止まった理由が画面上のどこにも無くなる
- 選ぶものが 1 つしか無い（フォルダを使っていない）ときは、選択そのものを出さない
- 購読管理でフォルダ名を入力するときは、既に使っている名前を候補に出す。選択肢ではなく
  候補に留めるのは、新しいフォルダをその場で作れなければならないため。手で打ち直すと
  表記ゆれ（「開発・WEB」と「開発・web」）が生まれ、分類が育たない

## 購読の解除と絞り込み

- **読んでいる最中の解除は左ペインのフィード名の行から。** キーは割り当てない（キー表に無いものを増やさない。購読管理の入口と同じ考え方）。普段は文字色を透明にして場所だけ取り、行に触れたときに出す。出したり消したりで幅が動くと、フィード名の折り返し位置が変わって読みにくい
- **解除の前に必ず確認する。** 取り消せず、記事も一緒に消える。解除後はカーソルが次の未読フィードへ移り、そのまま読み続けられる
- 購読管理画面では名前・URL・フォルダで絞り込める。突き合わせ先に URL を入れているのは、同じ名前のブログを URL で見分けたいことがあるため。「問題のあるフィードだけ表示」とは重ねて効く

## 見ているサイトの購読（issue #4）

- ブックマークバーに入れる 1 行を購読管理の下に置く。いま見ているページの URL を
  リーダーに渡して購読する
- **渡すのはページの URL で、フィードの探索はサーバがやる。** 購読管理に URL を貼るときと
  同じ経路を通る（探索の規則を 2 箇所に置かない）
- 押すと購読管理が開き、そのまま登録まで済む。**確認は挟まない**（押した本人が
  「このサイトを購読する」と決めて押している）。取り違えたら一覧からその場で解除できる。
  フィードが複数見つかったときだけ、いつもどおり候補を出して選ばせる
- **他のサイトから API を直接叩かせない。** 画面を開く形なら Cloudflare Access の
  ログイン済みセッションがそのまま使え、資格情報を配らずに済む
- 起動シーケンスが落ち着くまでは登録を投げない。途中で足すと、後から届く bootstrap の
  一覧（足す前のもの）に上書きされ、サーバには居るのに画面から消える

## 全文取得

要約しか配信しないフィード向けに、記事ページから本文を取ってくる設定。

- **切り替えは購読管理画面の「全文」だけ。** キーは割り当てない（読んでいる最中に切り替えるものではないので、キー表を増やさない）
- 既定は切。相手のサーバに記事の数だけ取りに行く動作なので、こちらから勝手に始めない
- 要約しか配信していないと見えたフィードには、購読管理画面で勧めの一行を出す
- 入れた直後にそのまま取りに行く。設定だけ変えて次の定期取得を待たせると「入れたのに何も変わらない」ように見える
- 切に戻すと、取得済みの本文も捨ててフィードの配信内容に戻る。抽出が本文でないものを掴んでいたときの戻し道なので、残す方を選ばない

## ヘルプ

`?` でキーバインド一覧をオーバーレイ表示。`keymap.ts` から自動生成する。

初回起動時は自動で表示する（キーボード操作前提の UI なので、知らないと何もできない）。
